# PRD 001 — Voice Capture and Local Storage

## Status
Delivered, v0.4.1.

## Goal
A single-user field tool that captures voice notes with their GPS fix, stores both on the device, and lets the user replay or delete them later.

## User story
As a field operator, I open the app on my phone, tap one big button, speak, and tap it again. The note saves instantly with my location attached. I can come back later, see my notes newest first, play them back, and tap a coordinate to verify the point on a map.

## Functional requirements

- Single dominant record/stop button. No form required before recording.
- Audio capture via `MediaRecorder`.
- Location capture via the browser Geolocation API.
- Recording starts the moment the microphone is granted. GPS is acquired in the background and attached to the recording when it arrives, so the first tap is not blocked on location.
- Each recording persists with its audio blob and metadata to IndexedDB.
- Newest recordings appear first in the list.
- Inline playback for every saved recording.
- Delete action for every saved recording.
- Inline confirmations replace blocking browser dialogs.
- Recording still saves when location is denied or unavailable, labelled accordingly.

## Data model

### Recording
- `id`: string
- `createdAt`: ISO timestamp
- `durationMs`: number
- `audioBlob`: Blob
- `mimeType`: string
- `latitude`: number | null
- `longitude`: number | null
- `accuracyMeters`: number | null
- `altitude`: number | null
- `locationCapturedAt`: ISO timestamp | null
- `locationStatus`: `"captured" | "denied" | "unavailable"`
- `source`: `"gps"`
- `note`: string | null

## Acceptance criteria

- One tap starts recording; one tap stops it.
- The record button is the dominant visual element of the page.
- Audio and metadata persist across a full page reload.
- GPS coordinates, accuracy, altitude (when available), and acquisition time are stored with each recording when permission is granted.
- Recordings still save when permission is denied or the GPS is unavailable, with `locationStatus` set to `"denied"` or `"unavailable"`.
- Newest recording appears at the top of the list.
- Each list item can be played back inline.
- Each list item can be deleted.
- App works offline after first successful load.
- Status is always visible: ready, recording, saving, or error.
- No blocking `alert()` or `confirm()` dialogs in the recording flow.
