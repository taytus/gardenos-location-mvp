# PRD 003 — Production GPS Only, Versioning, Cache Reliability

## Status
Delivered, v0.4.1.

## Goal
Ensure the deployed app captures and stores only real device geolocation, exposes a visible version that matches what is shipped, and survives a deploy cleanly so the operator always sees the latest build.

## Scope

### Production-only GPS

- No demo button, no preview button, no simulated path in production.
- No hardcoded latitude or longitude literals in production source. Production source is `index.html`, `sw.js`, and `manifest.webmanifest`.
- New recordings are tagged with `source: "gps"`.
- Geolocation is requested with `enableHighAccuracy: true`, `maximumAge: 0`, and `timeout: 20000`.

### Legacy demo purge

On startup the app scans IndexedDB for legacy demo records and deletes them. A record is considered legacy demo if any of the following is true:

- `source === "demo"`
- the record's `note` matches the legacy demo note string
- the record carries an explicit demo flag (for example `isDemo` or `record.demo`)

Records are matched on these attributes only. They are never matched or removed by coordinate value, so a real recording with poor accuracy is never deleted.

### Versioning

- A single `APP_VERSION` constant lives in `index.html`.
- The visible `v: X.Y.Z` badge in the header is rendered from `APP_VERSION`.
- The same string is mirrored in the `VERSION` file at the repository root.
- The release is tagged with `vX.Y.Z` in git.
- `manifest.webmanifest` and `sw.js` are referenced with a `?v=X.Y.Z` query string so the browser fetches the new copy after a deploy.

### Service worker and cache reliability

- The service worker exists at `sw.js` and is registered on first load.
- The cache name embeds the app version (for example `gardenos-location-v0.4.1`).
- On `activate`, the worker enumerates `caches.keys()` and `caches.delete()`s every cache whose name does not match the current version.
- The worker calls `skipWaiting()` and `clients.claim()` so a new version takes over without a hard reload.
- Navigation requests (HTML) use network-first, so a fresh deploy is visible after a refresh.
- Static assets use cache-first, so the app stays usable offline after the first load.

## Acceptance criteria

- `index.html` contains no hardcoded demo latitude or longitude literal, and no `latitude: NUMBER` or `longitude: NUMBER` assignment.
- `index.html` contains no demo button element and no demo path string.
- `index.html` declares `APP_VERSION = "0.4.1"` and renders the `v:` badge from it.
- `index.html` matches legacy demo records on `source === "demo"`, on an explicit demo flag, or on the legacy demo note string. Not on coordinate values.
- `sw.js` exists and parses as valid JavaScript.
- `sw.js` cache name includes `v0.4.1`.
- `sw.js` enumerates `caches.keys()` and calls `caches.delete()`.
- `sw.js` calls `skipWaiting()` and `clients.claim()`.
- `sw.js` distinguishes navigation requests and uses network-first for them.
- `sw.js` contains no hardcoded demo coordinate and no demo path string.
- `manifest.webmanifest` exists, is valid JSON, and includes `name`, `short_name`, `start_url`, `display`, `background_color`, `theme_color`, and `icons`.
- New recordings store `source: "gps"`, an `audioBlob`, a `mimeType`, a `durationMs`, an `accuracyMeters`, an `altitude` (when available), a `locationCapturedAt`, and a `locationStatus`.
- Recordings are stored in IndexedDB, not `localStorage`.
- Google Maps links use `https://www.google.com/maps/search/?api=1&query=`, never `google.com/maps?q=`.
- Every coordinate card carries the hint "Tap to open in Google Maps".
- No `window.confirm` and no `window.alert` in the recording flow.
